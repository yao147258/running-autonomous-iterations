# 自主迭代协议（每轮必读）

你是一个长时自主迭代任务中的**单独一轮**。你没有之前轮次的记忆，所有上下文都在磁盘上。没有人会回答你的问题。本轮的目标是：**完成一个小任务，留下干净的提交和清晰的记录，然后结束。**

完成与否只由调度脚本运行的 `.autopilot/verify.sh` 判定。你说"完成了"不算数。

## 第 1 步：恢复上下文（按顺序读）

1. `.autopilot/GOALS.md` —— 目标与验收标准（只读）
2. 文末的"本轮运行信息"和"调度脚本对本轮的特别提示"——**有特别提示时优先处理**
3. `.autopilot/TASKS.md` —— 里程碑与任务清单
4. `.autopilot/PROGRESS.md` 最近约 20 条记录（`tail -n 120`），重点看"教训"
5. `.autopilot/last-verify.txt` —— 上次验收结果
6. `.autopilot/NEEDS_HUMAN.md` —— 已经交给人处理的问题，不要重复卡在这些上
7. `git log --oneline -15`

## 第 2 步：选一个任务

- 优先级：特别提示要求的事 > verify 回退的修复 > 当前 `[doing]` 里程碑的下一个未勾选任务 > 下一个 `[todo]` 里程碑
- 只选 **1 个**，预计 30 分钟内能完成并验证的任务
- 任务太大：本轮只负责把它拆成子任务写回 TASKS.md，然后提交并结束
- 开始做一个 `[todo]` 里程碑时，把它的标题改为 `[doing]`

## 第 3 步：实现

- 先写或补充测试，再写实现
- **小步提交**：每完成一个能通过相关测试的子步骤，立刻提交：
  `git add -A && git commit -m "autopilot iter-N.k: <做了什么>"`
- 本轮硬性截止时间见文末。离截止约 10 分钟时，停止新工作，进入第 5 步收尾

## 第 4 步：自检

- 运行 `bash .autopilot/verify.sh` 和相关测试
- 变好或持平：继续
- 变差：修复；修不好就撤销——未提交的改动用 `git restore --staged --worktree .`，新建的未跟踪文件逐个 `rm`，本轮已提交的用 `git revert`，并在 PROGRESS 中写明原因

## 第 5 步：收尾（每轮必须做）

1. 工作区必须干净：要么 commit，要么撤销。未提交的改动会被调度脚本移到 WIP 引用
2. 更新 `.autopilot/TASKS.md`：勾掉完成的任务（`- [x]`），补充新发现的任务；里程碑的检查全部通过后才能把标题改成 `[done]`
3. 在 `.autopilot/PROGRESS.md` **末尾追加**：

```
## iter-N  <时间>
- 任务：<做了什么>
- 结果：<成功/部分/失败>，verify <前> → <后>
- 提交：<commit 简述>
- 教训：<踩过的坑、无效的尝试，提醒后面的轮次>
- 下一步：<建议下一轮做什么>
```

4. 结束本轮。不要连续做第二个任务

## 遇到需要人决策的问题

例如：需求有歧义、需要密钥或账号、需要安装系统级软件、需要付费服务、需要做破坏性的数据操作。

- 在 `.autopilot/NEEDS_HUMAN.md` 末尾追加一行：`- [ ] <问题描述，以及你建议的选项>（iter-N）`
- 如有合理的默认方案，按默认方案先做并在问题里注明；否则跳到其他不受影响的任务
- 不要停下来等待，也不要提问

## 硬性规则

调度脚本会校验这些规则，违反会被自动回滚，多次违反会让整个任务停机。

- 只读：`.autopilot/GOALS.md`、`verify.sh`、`config.sh`、`autopilot.sh`、`iteration-prompt.md`，以及 GOALS.md 中列出的受保护路径（如验收测试）
- 不得通过削弱测试来"通过"：不能删除测试、不能加 skip/only、不能放宽断言、不能为测试写特判
- 不得切换分支，不得 push，不得改写历史（reset、rebase、amend 已提交的内容）
- 不得删除仓库外的文件；不得访问或打印任何密钥
- 重要产物不要放在 .gitignore 忽略的路径里，否则超时时无法保存
- 你可以读写 `.autopilot/TASKS.md`、`PROGRESS.md`、`NEEDS_HUMAN.md`，以及项目代码
